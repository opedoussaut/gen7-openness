# GEN7 Cameo MBSE agent

Connects GEN7 to **CATIA Magic / Cameo** through **[cameo-mcp-bridge](https://github.com/ajhcs/cameo-mcp-bridge)** (MCP).
The agent is an MCP *client*: it starts the bridge's own MCP server (`python -m cameo_mcp.server`, stdio) and calls
its tools. It never edits Cameo files directly; everything happens in the open model, through the bridge.

```
GEN7 orchestrator ─► Cameo MBSE agent (this folder) ─MCP stdio─► cameo-mcp-bridge server ─HTTP 127.0.0.1:18740─► CameoMCPBridge plugin ─► CATIA Magic
```

| File | Role |
|---|---|
| `mcp_session.py` | MCP client session with per-call telemetry (tool, args summary, ms, ok, bytes) written to JSONL |
| `probe_capabilities.py` | Step 5–7: version, plugins, SysML, simulation, diagram types → `capabilities.json` |
| `build_model.py` | Builds the AI Factory Cooling System model from `model-spec.json` (phases, resumable via `state.json`) |
| `diagrams.py` | Ten diagrams with explicit layouts, routing, colours, then native Cameo PNG export |
| `run_workflow.py` | The demo workflow (connect → retrieve → evaluate → verify → export) → `workflow.json` |
| `live_server.py` | Live Cameo mode for the GEN7 page (`/status`, `/run` as Server-Sent Events) |
| `model-spec.json` | Generated by `node scripts/export-mbse-spec.mjs` from `src/engineering` — the single source of truth |
| `relay_shim.py`, `gen7-cameo-relay.ps1` | Only when the agent runs on another machine/VM than Cameo (file-queue relay to the loopback-only bridge) |

## Set up (on the Cameo workstation)

1. Install the bridge plugin in CATIA Magic (see the bridge README) and restart CATIA Magic. The Notification window shows
   `CameoMCPBridge: HTTP server started on port 18740`.
2. `python -m pip install -r requirements.txt` and `pip install -e <cameo-mcp-bridge>/mcp-server`.
3. Open the project (here `GEN7 DEMO.mdzip`).

## Build the model and export the diagrams

```bash
node scripts/export-mbse-spec.mjs > tools/cameo/model-spec.json      # from the repository root
cd tools/cameo
python probe_capabilities.py ../../evidence/cameo
for p in structure requirements loops system analysis profile names actions; do python build_model.py $p --out ../../evidence/cameo; done
for d in context system_v1 system_v2 internal_v1 internal_v2 thermal_flow traceability verification_v1 verification_v2 evolution; do
  python build_model.py diagram:$d --out ../../evidence/cameo; done
python build_model.py summary --out ../../evidence/cameo
python run_workflow.py --out ../../evidence/cameo
node ../../scripts/index-cameo-evidence.mjs                           # recorded evidence for the page
```

The model is created in a new package **AI Factory Cooling System (GEN7)**; nothing else in the project is touched,
and the project is **not saved** by the agent.

## Live Cameo mode

```bash
cd tools/cameo && python live_server.py        # http://127.0.0.1:18790
```

Open the GEN7 page with `?cameo=live#engineering` (local `npm start` or the GitHub-hosted page). The page checks
`/status`; if the agent answers, the badge reads **LIVE CAMEO** and *Connect to Cameo* streams real MCP calls.
If it does not answer, the page says so and stays in **Recorded Cameo evidence** mode.

## What is genuine, what is not

* Architecture, requirements, relationships, values and diagrams are created **in Cameo**, through MCP tools.
* Diagram images are **native Cameo exports** (`cameo_get_diagram_image`). GEN7 does not redraw them.
* The thermal-hydraulic calculation runs **in GEN7** (`src/engineering/physics.js`): Cameo Simulation Toolkit is not
  installed on the target workstation. The results are written into the model as test cases and say so.
* SysML **v1** (Cameo SysML plugin). The SysML v2 plugin is not installed; nothing is labelled SysML v2.
